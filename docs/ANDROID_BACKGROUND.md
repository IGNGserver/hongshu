# Android 后台实时连接与最近任务隐藏

## 用户操作

在“设置 → 实时广播与同步”中开启后台实时连接，允许通知，并按系统设置允许后台运行/自启动。
若手机需要最近任务加锁，可先加锁，再开启“不在最近任务列表显示”；应用无法判断加锁状态。
隐藏后可按首页返回或 Home 回到桌面，任务卡片不显示，实时服务继续运行；点击桌面图标或通知重新进入。
关闭隐藏开关即可恢复当前任务显示，无需重新安装。隐藏不会自动开启实时连接。
“开机恢复实时连接”默认关闭，只有实时连接开关也开启且凭据有效才尝试恢复。
通知的“停止”仅关闭实时连接，原有周期同步仍保留；重新开启需要主动操作。

## 系统边界

使用 Android 官方前台服务，不使用一像素窗口、无声音乐、无障碍服务或常持唤醒锁。
Android 14+ 使用 remoteMessaging，符合跨设备文本消息连续接收用途；旧系统使用 dataSync。
前台服务、忽略电池优化和任务隐藏都不保证永不被杀或锁屏网络永不延迟。
Android 13+ 未授权 POST_NOTIFICATIONS 时前台服务可以运行，但通知栏未必显示；页面必须提示。
Android 系统“强制停止”后必须主动重新打开应用；不使用 Worker/闹钟强行拉起服务。
厂商自启动入口不统一，提供应用信息与电池优化入口和人工配置说明，不谎报白名单/最近任务锁已开启。
不使用 finishAndRemoveTask：保留任务比销毁任务更有利于厂商任务锁兼容，但仍须实测。

## 验收矩阵（开发完成不等于这些真机场景已通过）

| 场景 | 预期与观测方式 |
| --- | --- |
| 开启/关闭隐藏；重开应用 | 当前 taskId 的 exclude 标记可逆、配置持久化，其他任务不受影响 |
| 首页返回、Home、设置/详情返回 | 首页退后台，子页面正常返回，服务不随界面退出 |
| 从桌面/短信通知/连接通知进入 | 复用主任务，不叠加重复主页面 |
| 先锁定再隐藏，一键清理 | 卡片隐藏；记录该厂商实际是否保留保护，不能由模拟器推断 |
| 连接/断网/网络恢复/中枢故障 | 通知与真实 socket 状态一致，恢复自动重连，无多个并发连接 |
| 普通进程回收、空 Intent 重建 | 开关开启且凭据有效时恢复；关闭/无凭据时不连接 |
| 通知“停止”、关闭实时连接、401 | socket/网络回调释放，无自动拉起；401 不清除后来更换的身份 |
| 重启、未开启开机恢复、凭据不可用 | 只在 opt-in 且系统允许时恢复，其他情况退回周期同步 |
| 拒绝通知权限/关闭连接渠道 | 页面明确提示通知不可见，不把开关当连接健康 |
| 强制停止、系统活动应用“停止” | 不主动绕过用户停止；强制停止后由用户重开 |
| Android 15+ 后台超过 6 小时/隔夜熄屏 | 确认 remoteMessaging 类型、真实新消息同步与耗电，不只看通知 |

自动测试使用合成凭据和本地测试消息，不读取用户短信、不连接生产中枢。真实验证记录写入 VALIDATION.md。
