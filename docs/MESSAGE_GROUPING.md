# 验证码与可选 AI 分组

## 产品契约

AI 默认关闭：全部、验证码、其他。开启后：全部、验证码、个人、通知、推广、垃圾、待分析。
按消息分类而非号码分类；全部始终包含垃圾。原文、时间、上传指纹与通知语义不变。
验证码由版本化规则识别，歧义不提取，有效期仅采用原文明示值；不自动复制或删除。
不做商户来源认证、摘要、系统拦截或自动退订；头像由客户端按发件人稳定生成。

## 数据与队列

单用户中枢沿用现有授权边界，不引入多租户。独立 message_analysis 保存提取结果、
AI 类别、人工覆盖、状态、有限重试、租约和修订号；外键随消息删除，旧结果不能复活消息。
新增短信同事务写入规则分析；历史规则回填按持久水位每批 100 条，AI 关闭时也执行。
回填不加载全库，不修改 messages 表；升级快照先按消息 ID 从近到远回填，完成后以正向水位补齐旧版写入的消息。
AI 开启即处理所有未完成的非验证码消息；新到消息优先，历史消息按时间从近到远。
数据库领取租约，每个中枢进程固定单并发，数据库锁保证多进程不重复领取且共享限速/额度；
崩溃到期可恢复；每条最多 3 次自动尝试，失败可手动重试。
领取分两阶段：候选 JOIN/排序在事务锁外以单条一致性读执行，同时读取该任务 revision，
仍按 `historical ASC, timestamp DESC, id DESC` 选首条，以本次选择开始时刻判定退避/租约到期。
随后短事务按 `ai_settings → 单条 message_analysis` 锁序读取最新配置，重验任务 revision、开关、限速/每日额度与
可领取条件，条件更新租约并在同一提交记账；不锁源 messages，不在 settings 锁内扫描/排序队列。
优先级针对每次候选查询的快照：快照中可领取的新到消息优先于历史消息，时间相同以 ID 降序决胜；
查询期间或之后提交的新任务参与下一次排序，不抢占已选出的有效候选。因此并发新消息可能等当前候选
领取后再处理；不要求领取提交时的全库严格优先级，也不因无关上传推进全局 revision 而取消本轮。
这使持续 OTP/低优先级历史上传不会阻断有效候选的领取。候选自身失效则不扣额度、不删除任务；
额度/租约时间在取得 settings 锁后重新取值，避免锁等待消耗新租约。
关闭/暂停停止新调用，已发请求可完成；重新开启保留完成结果。人工覆盖取消旧租约，
只有显式恢复自动分类才允许模型重新分类。修改服务配置使旧在途结果失效，但不重算完成消息。
分类修订独立于短信同步 ID；元数据增量接口仅传分析字段，不重复下载正文或触发新短信通知。

已读变更复用 `read_state.updated_at` 作为内部逻辑时间戳：有效标读在同一事务内按
`GREATEST(updated_at+1, 当前毫秒时间)` 推进，因此它不代表准确的墙上时钟时间。已读分页接口将其作为不透明 revision 返回，不改变短信或分析游标。
全局标读锁序为 `sync_clock → read_state`；会话标读先锁 `read_state`，不反向申请 `sync_clock`。
WS 仅读取三个单行状态（短信游标、分析修订、已读标记），不按连接重复扫描短信或计算未读数；
前端收到提示后仍通过 `/me` 的总数和短信游标刷新。
旧非法会话水位仅通过显式手动运行 `scripts/repair-read-watermarks.sql` 修复：先备份原值，审计仅输出数量，
事务内把无法对应同发件人现存消息的非零水位归零，并推进同一变更标记；合法水位和原始短信保留。

## 安全和调用边界

管理员在 Web 配置 AI 协议、地址与模型。支持 OpenAI Responses API、旧版 OpenAI-compatible Chat Completions、Anthropic Messages 和 Google Gemini Generate Content；本地模型仍可通过允许主机名单使用兼容协议。
Responses API 是新配置的推荐协议，已有配置默认保留 Chat Completions，避免升级后改变现有端点语义。
密钥以 HONGSHU_AI_SECRET（base64 的 32 字节部署密钥）AES-GCM 加密保存，响应仅返回是否已设置。
密钥不下发 Android、不写日志；备份需同时保留部署密钥。更换密钥前先解密并重新保存配置。
默认仅允许公网 HTTPS；私网/本地模型须部署者显式设置 HONGSHU_AI_ALLOWED_HOSTS（精确主机名，逗号分隔），
拨号时重新解析并检查地址，不跟随重定向，不使用环境代理。该白名单是有意授予的内网访问权限。
启用时明确说明历史与新增非验证码正文会发送到配置服务。仅发送当前一条正文，不发送通讯录、
设备、接收号码或历史会话；默认遮蔽长数字、邮箱和 URL，脱敏不能保证匿名。
仅允许固定类别 JSON；短信是数据，不赋予工具或执行能力。验证码不送 AI；模型自报置信度不作为认证。
每分钟限速、每日调用额度（含失败尝试）和单请求输出 token 上限限制消耗；不声称可精确核算货币费用。

连接测试同步等待模型，仅该测试响应将写入 deadline 调整为配置超时（2–60 秒）加 5 秒响应余量；
其他路由保持默认写入超时。模型请求仍受配置超时约束。

配置/鉴权/限流异常暂停队列，手动恢复；普通网络错误有限退避。失败和无法分类仍在待分析中可见。

## 迁移与回滚

006 迁移仅新增派生表和默认关闭的配置。历史规则回填会逐步完成，未回填期间原始短信仍可在全部查看。
先升级中枢，再升级客户端；旧客户端忽略新增字段，原 /sync 游标不变。
回滚先关闭 AI、停止新服务，再回退二进制；保留新增表可重新升级。
必须删除派生数据时先备份，再执行 006 down，最后删除对应 schema_migrations 记录；不删除原始短信。
Android SQLite v7 仅新增派生元数据和同步水位，不清空 inbox/outbox/采集账本。

## 验收

规则中英文/字母数字/歧义/金额日期干扰；关闭 AI 无外发；历史自动排队；新消息优先；
租约重启恢复；配置变更和人工纠正竞态；分页筛选/计数一致；分类增量同步不触发通知；
密钥不泄漏、输出严格验证、私网默认拒绝。测试仅使用合成数据与模拟 AI，不调用真实外部模型。

`server/analysis_claim_test.go` 在真实 MySQL 上以查询响应屏障验证：候选读取未返回时上传仍能提交，
每轮读取期间都有 OTP/低优先级历史上传仍能逐轮领取，并发新消息在下一次排序优先；
双 worker 不重复领取或超额度，失效候选/过期租约不会丢任务。
CI 的 `go test -race -count=1 -v ./...` 输出 10,000 条合成队列的 `EXPLAIN ANALYZE` 与上传/领取耗时；
该规模仅作锁范围回归与诊断，不代表大库吞吐量保证。未设置 `TEST_MYSQL_DSN` 时这些测试跳过，不能视为数据库验证通过。
