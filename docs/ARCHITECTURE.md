# 鸿枢首版架构

单用户中枢、Go HTTP/WebSocket 服务、MySQL 8.0+、原生 Web/PWA、Kotlin Compose Android。
所有已授权设备能读全部短信，管理员能管理/撤销设备；不实现多租户、发送短信、MMS/RCS。

验证码、可选 AI 分组、持久队列和独立元数据同步见 [MESSAGE_GROUPING.md](MESSAGE_GROUPING.md)。

## 可靠性与业务标识

- 接收号码由用户确认，SIM 的系统 subscription ID 仅是本设备映射，不是跨设备标识。
  卡槽不能代替订阅 ID：换卡或卡槽对调后不得把新卡短信记到旧号码。手动模式只填写 SIM1/SIM2
  手机号，可扫描填入后保存；保存时由系统解析订阅 ID，不向用户暴露技术字段。
  自动模式只显示匹配状态，保存后持续跟踪订阅变化，后台同步/补扫刷新号码；广播保存前不调用 SIM 服务。
  系统没有提供有效号码时，自动模式允许用户只为该卡手填号码；手填号码绑定订阅 ID，
  同一张卡后续扫描仍取不到号码时保留，换卡（新订阅 ID）从空白开始，不猜测。
  手动模式允许某张卡留空表示不同步，但至少映射一张卡；旧短信已捕获的号码快照保持不变。
  保存唯一活动 SIM 后可为来源未知的短信兜底，换卡或多卡自动失效；已知未映射订阅不兜底。
- 会话按发件人分组。同一短号发给多张 SIM 仍是一个会话，详情保留每条短信的接收号码；来源设备仍是过滤维度。
  可选联系人名称按号码共享。
- Android 广播将多段 PDU 合并，先写 SQLite outbox，再由 WorkManager 上传。
  标准 SMS_RECEIVED 是不可中止广播，优先级不是厂商兼容或可靠性保证。
  实时接收只依赖 RECEIVE_SMS，不依赖 READ_SMS、历史扫描或网络；广播先短事务落库，再唤醒同步。
  保存时只使用已确认的精确订阅映射，未知来源保留正文，不按当前卡槽猜测号码。
  采集开关和身份切换递增持久代次；异步广播与历史批次提交前复核代次，旧任务不能写入新身份。
  历史查询及 SIM 刷新不占用身份锁；每批至多 100 条的事务才占锁，不让外部 provider 阻塞广播。
  未配置 SIM 号码时先保留，配置后补传；HTTP 提交确认之前不删除 outbox。
  “补齐历史短信”独立控制 READ_SMS 扫描；已有用户继承原历史采集意图，新用户需主动开启。
  首次自动扫描持久保存历史边界；扫描按 provider ID 分页，进度与捕获账本同事务提交，
  不以连接时间过滤旧短信。开机、打开应用、权限授予和每次同步均继续补扫。
  v4→v5 升级保留队列/账本/映射，仅重置扫描水位一次以补齐先前被连接时间过滤的历史。
  v5→v6 仅增加无正文的实时采集计数/时间及队列时间索引，不重置历史水位、队列、映射或去重账本。
  本机待同步页面直接分页读取 outbox，与中枢收件箱分开；未映射、异常及中枢禁止上传均可见。
  provider 行身份与广播/通知捕获账本独立于 outbox 保留，ACK 不删除判重证据。近似匹配仅连接同一
  本机/SIM 的广播、provider 与通知记录，不合并两个独立 provider 行或远端设备消息；
  一方缺订阅 ID 时可配对并继承另一方的 SIM，双方都未知则不按正文合并。
  用户强制停止后系统不再投递广播，必须重新打开应用。
- 历史导入标记 historical，只更新历史与实时会话视图，不触发跨设备新短信通知，避免导入通知风暴。
  导入时间使用收件箱 date（本机接收时间）。它和广播 PDU 时间可能不同，不能靠改时间戳假装去重；
  已有广播记录时，同设备、同发件人、同正文、时间差在 2 分钟内的导入行视为同一条，不重复入库；
  同步页还会按本机设备和完整指纹修复已提交但 ACK 丢失的 outbox。
- 去重指纹为 SHA256(接收号码 NUL 发件人 NUL 毫秒时间 NUL 正文)，唯一键包含来源设备。
  相同来源的历史导入和广播可去重，不错误地合并不同设备收到的同一短信。
- 服务端事务锁定 singleton sync_clock，分配提交顺序 ID、存储短信、创建推送任务后提交。
  不能使用普通 AUTO_INCREMENT 作为可靠游标（并发事务提交顺序可能与 ID 不一致）。
  同一批里未确认接收号码的条目返回错误并不入库，已确认条目仍提交；客户端只删除已确认条目。
- 初次同步基线与完成状态独立持久保存，不以非零游标判断完成。待通知意图与同步页同事务保存，
  页面中断后重试仍能通知；连接之后由其他设备上传的非历史短信发一条汇总通知。
- `/sync?after=N` 升序分页；客户端必须将本地消息与游标在同一事务保存。无历史自动清理。
  Web 没有持久消息缓存，只观察 /me 的 head 与 epoch，并按需分页读取显示历史；空更新保留阅读范围和位置。
- sync_clock.epoch 随逻辑备份一起保存，新库默认 1，升级旧库也为 1。它不会随短信提交增加。
  恢复前记录现行 epoch，恢复后设置为高于现行与备份值的代次，禁止仅对备份值加一。
  每个同步页面写入前检查 epoch；客户端第一次见到 epoch 只记录；
  之后若变化，清空已同步缓存和游标并从头补齐，不删除尚未上传的短信，也不清除本机捕获账本。
- 同步 ID 只决定提交顺序；会话/对话按短信时间与 ID 排序，历史导入不能盖过真正的新短信。
  conversation_heads 与上传同事务维护每个发件人的最新消息；无搜索、SIM 或设备筛选的会话查询读取摘要，不重新计算全部历史。对话详情始终按发件人读取全部接收号码的短信。
  搜索正文或按来源设备过滤仍从匹配历史计算会话，分页不代表海量搜索已压测。
- WebSocket 只发无正文的更新提示，连接/重连及周期轮询均执行增量补齐。
  提示覆盖其他设备的新短信，也覆盖本机上传后其他客户端需要看到的变更；来源设备是否弹通知由客户端判断。
- Web Push 队列只服务已订阅的浏览器。失败不能回滚短信。发送前领取 60 秒租约，避免同一进程重叠发送；崩溃后租约到期可重试。过期订阅 404/410 只删除该 endpoint 自己的任务和订阅，不删除短信，也不清掉同设备其他积压任务。
  推送默认仅显示“有新短信”。Android 不依赖 Web Push：实时服务在线时由 WS 触发本地通知，否则由 WorkManager 补齐后通知。
  来源设备不创建自己的推送任务。
- 备份使用一致性逻辑备份，包含授权、消息、游标、队列和 epoch；恢复必须同时保留部署密钥。
  恢复后必须生成不复用的 sync_clock.epoch，否则客户端会把重用的短信 ID 当成已经同步过。

## 身份与安全

系统不建立用户名或用户表。部署配置一个中枢密码，Web 登录不校验用户名；密码允许弱密码但不能为空，服务端用带随机盐的 Argon2id 校验器驻留内存。
所有设备（Web 与 Android）统一使用单一中枢密码登录接入；Web 默认赋予管理员权限，Android 赋予普通设备权限。
每设备独立 256-bit bearer，数据库只存 SHA256；撤销最后一个管理员设备后，仍可用中枢密码重新登录创建管理员身份。
Web 身份使用 HttpOnly / SameSite=Strict cookie，HTTPS 时 Secure；HTTP 时为支持明文部署不设置 Secure；不将凭据放 localStorage。
Android 使用 Keystore AES-GCM 保存凭据。撤销身份阻止后续 HTTP/WS/Push。
Android 禁用应用备份，并通过 Android 12+ dataExtractionRules 明确排除云备份和设备迁移的全部应用数据；厂商迁移行为仍需真机验证。
浏览器写请求检查 Origin；WS 检查 Origin；不提供跨域访问。HTTPS 代理必须配置 HTTPS PUBLIC_URL；
登录 Origin 的 HTTPS scheme 也强制 Secure cookie，不能被 HTTP 默认配置降级。
公网 HTTP 会明文传输密码、短信和会话凭据，强烈建议使用 HTTPS 或 VPN。
浏览器 Service Worker、可安装离线应用和 Web Push 需要 HTTPS 或 localhost；公网 HTTP 下不可用。
推送服务只能访问公开 HTTPS 地址，解析与拨号均阻止私网/回环，防止订阅接口成为 SSRF 通道。
不记录请求正文、Authorization、Cookie、凭据、短信、号码或 Push endpoint。
数据库/备份具有全部短信明文，部署者必须保护磁盘、备份和网络；首版不是端到端加密。

## Android 系统边界

“同步本机短信”开启时仅请求 RECEIVE_SMS；“补齐历史短信”单独请求 READ_SMS，拒绝历史权限不阻断实时保存。
实时、历史、队列与中枢健康分开呈现；只在实际保存后显示采集成功，权限授予不等于广播投递已验证。
诊断仅包含计数、时间和固定错误类别，不持久化或导出短信正文、号码、验证码、凭据及完整广播 extras。
“接收全部通知”表示中枢其他设备的新短信通知，不是读取其他应用的通知历史。
连接设置始终提供保存：首次登录传入名称，已连接且地址不变时 PATCH 本设备名称，不新建设备身份。
更换中枢或填写新密码时重新认证；旧中枢还有待传短信时阻止切换，失败保留原凭据。
开机补扫需要 RECEIVE_BOOT_COMPLETED，始终调度 WorkManager；仅在用户同时开启实时连接和
“开机恢复实时连接”、凭据可用且系统允许时启动实时前台服务，不在解锁前读取 Keystore 凭据。
SMS_RECEIVED 广播与通知链路独立，普通查看设备无需短信权限。
WorkManager 使用网络约束和指数退避，应用打开时也触发上传/补齐。
可选“后台保活”开关独立于短信通知开关。Android 14+ 使用 remoteMessaging 前台服务支持跨设备
文本消息连续接收；Android 8–13 使用 dataSync 兼容路径。周期补扫/批量上传仍由 WorkManager 执行。
连接通知根据连接、断网、重连状态更新；关闭通知权限/连接渠道时明确提示，不以通知存在冒充连接成功。
服务使用 START_STICKY 请求普通回收后的恢复，处理空 Intent 和重复启动；用户主动停止先持久关闭实时开关。
网络切换触发断开/重连，回调、socket 和协程随服务释放；不依赖 onTaskRemoved/onDestroy 被系统执行。
界面分别显示短信读取/队列/中枢同步状态、实际服务与省电状态、通知权限/渠道/接收链路状态，不以开关值冒充健康。
Android 15+ 的 dataSync 有 6h/24h 限制；跨设备实时链路不同时激活 dataSync 类型，避免附带该配额。
Manifest 声明两个兼容类型，但 startForeground 在 API 34+ 仅传入 remoteMessaging。
remoteMessaging 不代表免于系统回收、Doze 或厂商省电；启动失败退回周期同步，不通过重启/定时器绕过限制。
“不在最近任务列表显示”是独立且默认关闭的本地设置，按当前 Activity 的 taskId 设置
setExcludeFromRecents，可随时恢复显示。首页返回退到后台而不移除任务；详情/搜索/设置保留原导航。
桌面图标、短信通知和连接通知复用主任务。应用不能检测/设置厂商最近任务锁，也不保证隐藏后锁定仍有效。
UI 定时刷新/轮询仅在页面可见时执行；退后台后由服务和 WorkManager 承载同步，不依赖保留的 Compose 界面。
关闭实时服务仍有周期补齐（系统调度不保证准点）。用户强制停止后必须重新打开应用。
不申请无障碍，不假装默认短信应用，不绕过验证码/受限权限政策。

### Android UI 导航与系统栏

- Android Compose 页面由 `MainActivity` 维护统一的目的地栈：首页、会话详情、搜索状态和设置层级均按栈顺序处理返回；设置子页之间不能用单一可空页面值替代历史。
- 设置页作为同一 Activity 内的全屏目的地渲染，不创建独立的全屏 Dialog Window。关闭按钮关闭整个设置流程，系统返回和顶部返回按钮只弹出一级；首页根层返回继续将任务移到后台。
- Activity 使用 edge-to-edge。页面背景延伸到状态栏和导航栏区域，状态栏安全内边距只应用于顶部栏，导航栏/输入法内边距只应用于可交互内容，避免重复 inset 造成顶部空隙。
- AndroidX `PredictiveBackHandler` 消费系统返回进度。当前页与上一级页面同时参与动画，页面位移方向跟随系统手势起始边缘；取消手势不改变目的地栈，低版本和非手势返回使用普通弹出动画。
