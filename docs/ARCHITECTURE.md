# 架构起点

## 目标形态

鸿枢面向自部署场景，预期由以下组件组成：

```text
Android client ─┐
                ├─ HTTPS/API ─ Go hub ─ MySQL
Web/PWA client ─┘
```

这只是初始化阶段的边界图，不是已经承诺的接口、认证或部署方案。Go 中枢将负责跨设备同步协调和服务端 API，MySQL
负责持久化；Android 与 Web/PWA 的职责、同步方向和离线行为需要在后续设计任务中确认。

## 初始目录契约

- `android/`：只放 Android 工程及其测试；
- `web/`：只放 Web/PWA 工程及其测试；
- `server/`：只放 Go 中枢、服务端测试和服务端工具；
- `db/migrations/`：按顺序编号、可审计的 MySQL 迁移；
- `docs/`：跨组件协议、ADR、部署和安全说明。

## 后续设计必须回答的问题

1. 短信正文、联系人、附件和设备标识分别如何建模、加密和保留；
2. Android 端所需的系统权限、后台限制、用户授权和撤销路径；
3. 设备注册、认证、密钥轮换、端到端加密与服务端可见性边界；
4. 同步游标、重复投递、断线恢复、冲突处理和删除传播；
5. Web/PWA 的离线缓存、设备管理、导出和注销行为；
6. MySQL 迁移、备份、恢复、数据清理和版本兼容策略；
7. Docker/反向代理/HTTPS 的部署基线与健康检查。

每项决定应通过 ADR 或相关文档记录，并同步 API、数据库迁移、客户端实现与测试。没有明确决定前，不要把占位目录扩展成带有隐含产品承诺的业务代码。
