# 鸿枢 v0.1.0-alpha.16

本版本修复 Android 客户端在后台接收验证码与新短信时的调度竞态与漏收恢复缺口，增加独立的新短信收件箱补漏机制与系统短信权限诊断。版本仍属 alpha，为预发布版本，不是稳定版。

## 变更与修复

- **广播处理与任务入队生命周期修复**：`SmsReceiver` 的 `goAsync` 生命周期保持至 WorkManager 持久任务完成调度，避免进程在入队前被回收导致漏传。
- **运行中同步后继调度竞态修复**：当后台同步任务正在执行时，新到达的短信允许追加最多一个后继任务，解决新短信被合并忽略的问题。
- **新增“新短信补漏”**：针对系统未向鸿枢投递 SMS 广播的情况，提供独立且默认关闭的补漏开关；开启时仅读取开启之后的新短信，不隐式导入全量历史，且与历史扫描使用独立 provider ID 水位，共用去重账本与 ACK。
- **系统短信权限与策略诊断**：设置页提供系统广播实际到达次数统计、`RECEIVE_SMS` 与 `READ_SMS` 的 AppOps 访问策略展示，并支持手动“立即读取并检查收件箱”。
- **状态提示规范化**：收件箱查询新增 0 条不再误提示“读取正常”，而是如实说明仅代表当前可访问收件箱未发现新短信。

## 升级与回滚

中枢部署基于发布镜像标签（如 `0.1.0-alpha.16`）。升级时拉取新镜像并重启：

```bash
docker compose pull hub
docker compose up -d hub
curl --fail http://127.0.0.1:18473/healthz
```

如需回滚，在 `.env` 中使用上一版本镜像标签 `0.1.0-alpha.15` 并重新执行上述步骤。

## 验证边界

本机已完成仓库完整性校验、SemVer 校验、Go 服务测试与构建、Web 生产资源校验、Android 50 项单测/lint/APK 构建。CI 自动化覆盖 API 28、33、35 模拟器设备测试。
特定厂商系统（如小米澎湃 OS、各家验证码保护策略）针对验证码类短信的系统级广播筛选或隐藏，仍需在目标真实手机上按诊断文档进行实测。
