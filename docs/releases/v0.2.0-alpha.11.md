# 鸿枢 v0.2.0-alpha.11

本版本在 v0.2.0-alpha.10 基础之上，正式上线跨设备「发出短信同步」完整闭环（服务端方向隔离与 Web 展示适配 + Android 本机发出短信采集与自动上传）。仍为 alpha 预览版，不是稳定版。

## 本次更新

- **中枢消息收发方向隔离与能力声明**：
  - 数据库迁移 `011_message_direction`：`messages.direction`（`in`/`out`，默认 `in`）；
  - `POST /api/messages` 支持收录发出的短信（`direction: "out"`），指纹自动追加方向标识，与接收短信收录入同一号码会话；
  - 发出的短信不计未读数、不触发 Web Push 推送任务、不自动提取验证码，避免将发出的验证码当做本人收到；
  - `/api/me` 接口新增 `features: ["outgoing_sms"]` 能力声明，兼容旧版客户端。
- **Web/PWA 端发出的短信展示适配**：
  - 发出的短信气泡靠右对齐展示，采用 primary-container 强调色区分，隐藏分类菜单；
  - 时间戳显示“由 SIM卡名称 发出 · 已发送”，会话预览列表显示“我：”前缀；
  - 收发两个方向的气泡不再合并为同一簇。
- **Android 客户端发出的短信自动采集与同步**：
  - 监听系统短信库变化，增量扫描已发送箱（`type=2`）；
  - 自动匹配对端号码，与接收短信归并至相同会话；
  - 设置中新增采集开关“发出的短信”（默认开启）与“补齐历史发出的短信”；
  - 连接未升级的旧版中枢时，本地发出短信自动暂存等待，中枢升级后自动续传；
  - 本地 SQLite 升级至 v14，支持断网重试与去重账本。

## 升级与回滚

中枢升级：将部署目录 `.env` 中的 `HONGSHU_VERSION` 修改为 `0.2.0-alpha.11`，执行：
```bash
docker compose pull hub
docker compose up -d hub
```
中枢会自动执行数据库迁移 `011_message_direction`。

如需回滚，可将 `HONGSHU_VERSION` 改回 `0.2.0-alpha.10` 并重新拉起容器。注意：回滚迁移 011 会删除中枢已保存的发出短信记录（手机端原件不受影响）。
