# 鸿枢 0.2.0-alpha.27

本版本为 alpha 预览版，修复 Android 移除 SIM 卡后本地与中枢仍残留旧卡的问题，并让 Android 与 Web 对历史线路统一回退显示尾号。无数据库 schema 迁移，可从 `0.2.0-alpha.26` 平滑升级。

## 本次更新

- **拔卡后不再显示旧卡**：手机不再报告某个订阅（拔卡、停用 eSIM）时，Android 会清理本地 SIM 映射。自动模式随同步刷新；手动模式在回到前台、授予权限和 SIM 设置页扫描时做只删不增的对账，扫描失败或返回空集合视为不可信、不清理，避免误删有效号码。
- **历史线路按尾号显示**：旧短信已捕获的接收号码快照保持不变，没有当前映射的线路在首页筛选、会话标签和 Web 端统一显示为「尾号 xxxx」，不再声称它是当前卡槽。待上传页的「指定号码」、引导完成态和自动忽略开关也不会再把旧卡当成现存。
- **中枢 SIM 清单同步**：`PUT /api/sims` 新增 `{sims:[...]}` 全量替换形态（能力 `sim_inventory`），Android 在每轮短信与通话上传结束后同步当前映射并删除已拔卡的行，Web「设备与 SIM」、筛选菜单和空态计数随之更新；旧客户端的单条增量注册形态保持不变。
- **兼容性**：中枢与 Android 同版本时才启用全量替换；旧中枢没有该能力时客户端保持逐号码增量注册，残留清单等中枢升级后的下一次同步清理。旧版中枢、Web 与 Android 均可继续按原协议工作。

## 已知边界

- 没有真机双卡验证：拔卡/插回、eSIM 停用启用、运营商不暴露号码的 ROM 仍需现场验收。建议按「插两卡同步一次 → 拔卡后等一次同步或重开应用 → 首页/设置/待上传/Web 检查 → 插回卡恢复识别」确认。
- 本机没有 MySQL 实例，真实 MySQL 集成测试由 CI 的 MySQL service 执行；Android instrumentation 由 CI 模拟器矩阵（API 28/33/35）执行。

## 升级与回滚

中枢无需新增数据库迁移：在部署 `.env` 中将 `HONGSHU_VERSION` 更新为 `0.2.0-alpha.27`，执行 `docker compose pull hub && docker compose up -d hub` 即可升级。如需回滚，只需将 `.env` 中的 `HONGSHU_VERSION` 改回原版本（如 `0.2.0-alpha.26`）并重新执行 `docker compose up -d hub`。Android 直接覆盖安装同签名 APK，不清除已有数据。
