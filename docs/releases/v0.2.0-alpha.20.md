# 鸿枢 v0.2.0-alpha.20

本版本在 v0.2.0-alpha.19 基础上改进后台实时短信投递、PWA Push 刷新和旧版 Android 并发数据库打开。仍为 alpha 预览版，不是稳定版。

## 本次更新

- **Android 后台实时执行**：已由用户开启的前台实时服务直接运行上传/下载；短信广播、收件箱变化、WebSocket 提示和界面触发不再只排入 WorkManager。WorkManager 仍保留持久重试。短信补读独立于网络同步，只在用户同意边界内读取最近 100 行，不推进历史扫描游标。
- **同步状态可信**：区分 WebSocket 握手与短信同步健康；同步持续延迟或失败时，连接通知会明确提示。通知补读与号码/名称配对窗口由服务定时器承接，不因历史任务排队而无限等待。
- **PWA Push**：Push 到达后向已经打开的页面发送不含正文的刷新提示，不依赖可能已失效的 WebSocket；Service Worker 不下载或缓存短信正文。
- **Android 数据库并发修复**：串行化同进程 SQLiteOpenHelper 的连接首次打开/版本检查，避免 Android 9 及更早系统上多个组件并发打开数据库时重复建表；增加并发首次建库和升级回归测试，保留原短信队列及游标。
- **兼容性**：中枢 API 和数据库 schema 不变；Android 本地数据库版本不变；无需清除应用数据。仍需在真实手机上验收锁屏、Doze、双卡和厂商后台限制。

## 升级与回滚

升级中枢前备份数据库和 `.env`，将部署目录的 `HONGSHU_VERSION` 设为 `0.2.0-alpha.20`，然后运行：

```bash
docker compose pull hub
docker compose up -d hub
curl --fail http://127.0.0.1:18473/healthz
```

本版本不修改服务端 schema；健康检查或迁移检查失败时，将 `HONGSHU_VERSION` 改回 `0.2.0-alpha.19` 并重新创建 hub。保留数据库卷，不运行 `docker compose down -v`。Android 更新可直接覆盖安装；回退 APK 前确认 Android 数据库兼容，不要清除应用数据。

## 验证

- 合并前完整 PR CI 将执行仓库检查、Go race/真实 MySQL/vet/build、Web 测试/build/browser smoke，以及 Android API 28/33/35 单测、lint、构建与设备测试。
- Release 工作流会在 tag 后重新校验源码、签名 APK、部署包和镜像，并发布为 **Pre-release**；最终资产及工作流结果以 GitHub Release 页面为准。
- 模拟器/CI 不代替目标手机后台验收；不能据此承诺被系统强制停止或扣留短信时仍即时投递。
