# 鸿枢 v0.2.0-alpha.19

本版本在 v0.2.0-alpha.18 基础上，把验证码纳入 AI 复核链路：规则仍即时识别并展示验证码，AI 开启后再以独立 `otp` 类别复核分组并提取验证码文本。仍为 alpha 预览版，不是稳定版。

## 本次更新

- **验证码即时识别不变**：入库事务内仍由版本化规则同步提取，命中后立即出现在验证码组，AI 未完成也不影响用户找码。
- **AI 复核与提取**：AI 开启后验证码短信进入现有持久队列；AI 返回 `category` 和 `otp`，以 `otp` 作为独立分类并提取验证码。AI 完成时以 AI 分类为最终分组，未完成、失败或关闭时回退规则结果。
- **严格校验与恢复**：AI 码必须逐字出现在原文，长度 4–8、字母数字或连字符且至少一位数字，边界不允许截断更长号码；规则码保留在 `message_analysis`，人工把分类改回“验证码”可恢复展示。
- **脱敏例外**：验证码类短信发送给 AI 时保留数字以便提取，链接和邮箱仍脱敏；同意文案明确说明验证码正文会发送。AI 默认关闭。
- **历史与客户端**：旧规则验证码行通过领取条件懒纳入队列，不批量改 `state`，不需要数据库迁移；Web/Android 显示验证码的 AI 复核状态并允许手动归类，Android 只在无服务端分析时使用本地规则兜底。
- **兼容性**：无数据库 schema 迁移；不改短信原文、上传指纹、同步游标或通知语义。AI 关闭时仍只有全部/验证码/其他三个入口。

## 升级与回滚

升级中枢前先备份数据库和 `.env`，把部署目录的 `HONGSHU_VERSION` 设为 `0.2.0-alpha.19`；如果要启用 AI，先在未跟踪的 `.env` 设置 `HONGSHU_AI_SECRET`（见部署文档），然后运行：

```bash
docker compose pull hub
docker compose up -d hub
curl --fail http://127.0.0.1:18473/healthz
```

本版本不改数据库 schema；若健康检查失败，把 `HONGSHU_VERSION` 改回 `0.2.0-alpha.18` 并重启 hub，不要删除数据卷。数据库、备份和既有设备授权不受影响。开启 AI 后验证码正文会发送到配置的服务；已开启 AI 的部署应重新查看并保存新的同意文案。
