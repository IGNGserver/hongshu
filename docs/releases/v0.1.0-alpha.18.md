# 鸿枢 v0.1.0-alpha.18

本版本针对小米澎湃 OS（HyperOS）上“系统广播到达 0 次、收不到新短信”的问题，加入厂商授权诊断、收件箱即时补漏与可选的短信通知兜底。版本仍属 alpha，为预发布版本，不是稳定版。

## 本次更新

- **澎湃 OS 厂商授权诊断**：在“同步控制”中显示自启动、通知类短信、开机启动三项小米私有授权的实际状态；系统不允许读取时显示“无法读取，请人工确认”，不再把标准短信权限“已授予”误报为可接收。
- **一键跳转系统设置**：提供自启动管理与权限编辑（通知类短信）入口，找不到对应页面时回退到应用详情；页面提示省电策略设为无限制、关闭免费网络短信与 5G 消息。
- **收件箱即时补漏**：开启新短信补漏或历史读取后，应用运行期间系统收件箱一有变化，约 3 秒内自动补扫，不再只依赖 15 分钟周期任务；小米设备上提供“开启新短信补漏”推荐按钮（仍需手动开启）。
- **短信通知兜底（默认关闭）**：系统既不投递短信广播、收件箱也读不到时（如通知类短信、5G 消息），可授予通知使用权，从短信应用通知中采集开启之后的新短信；只处理短信应用通知，与广播/补漏按正文 ±2 分钟去重，后到的广播或补漏会把记录校正为准确号码与 SIM。
- **诊断文案**：系统从未投递广播时直接提示需要检查的厂商授权与兜底开关。

## 使用建议（澎湃 OS）

1. 设置 → 同步控制，按“厂商短信授权”按钮开启自启动与通知类短信，省电策略设为无限制。
2. 在小米短信设置中关闭免费网络短信与 5G 消息。
3. 开启“新短信补漏”；仍收不到时开启“短信通知兜底”并授予通知使用权（系统提示受限设置时，先在应用信息右上角允许受限设置）。
4. 用另一台手机发一条普通短信，确认“系统广播到达”次数或“短信通知兜底”到达次数增加。

## 升级与回滚

Android 本地数据库结构不变（仍为 v6），可直接覆盖安装；新开关全部默认关闭。中枢服务端 API 与 schema 无变化，镜像按版本标签发布（如 `0.1.0-alpha.18`）。升级时拉取新镜像并重启：

```bash
docker compose pull hub
docker compose up -d hub
curl --fail http://127.0.0.1:18473/healthz
```

如需回滚，在 `.env` 中使用上一版本镜像标签 `0.1.0-alpha.17` 并重新执行上述步骤；Android 系统不允许直接降级安装，卸载会清除本地待同步队列，不建议回退 APK；关闭“短信通知兜底”与“新短信补漏”即恢复 alpha.17 的采集行为，并可在系统设置中撤销通知使用权。

## 验证边界

本地与 CI 已运行 Android JVM 单测（含厂商授权、通知解析与跨来源去重）、lint、APK 构建，以及 Go/MySQL、Web 与 API 28/33/35 模拟器设备测试。小米私有授权代码与安全中心页面未公开文档化，各 HyperOS 版本的读取结果、跳转页面与短信通知字段仍需在目标真机上按 [HYPEROS_SMS.md](https://github.com/IGNGserver/hongshu/blob/main/docs/HYPEROS_SMS.md) 的矩阵验收。
