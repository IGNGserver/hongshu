# 鸿枢 v0.1.0-alpha.5

Compose 默认宿主端口调整为 `18473`，以减少与常见 Web 服务端口冲突。本版本是 GitHub **Pre-release**，仍属 alpha，不是稳定版。

## 新增与调整

- 新部署的 Compose 默认发布 `127.0.0.1:18473`，并转发至容器内 `8080`；可继续通过 `PORT` 覆盖宿主端口。HTTPS 反向代理的上游默认端口相应改为 `18473`。
- 已有部署的 `.env` 若包含 `PORT=8080`，该显式值会继续生效，不会被升级覆盖。需要切换时手动改为 `PORT=18473`；若使用直连 HTTP，也要同步更新 `PUBLIC_URL`。使用 HTTPS 反向代理时，外部 origin 可保持不变，但代理上游需指向新端口。
- 不修改容器内服务端口 `8080`，不修改数据库 schema，也不需要迁移现有短信、设备或授权数据。

## 升级与回滚

升级时备份 `.env` 和数据库，然后调整上述端口配置并运行 `docker compose up -d hub`。健康检查通过后，再验证 Web/Android 客户端访问。

回滚时将 `PORT` 恢复为原值（默认旧配置为 `8080`），并恢复对应的 HTTP `PUBLIC_URL` 或反向代理上游，然后重建 hub。保留数据库卷和备份；不要对生产数据卷运行 `docker compose down -v`。

## 验证边界

发布工作流会运行隔离 MySQL 上的 Go race/integration 测试、真实浏览器 smoke test，以及 Web、Android 和 OCI 构建。实际公网可达性、HTTP 明文风险与 Android 真机行为仍需部署者单独验收。

## 资产与性质

Release 包含 Linux amd64 中枢/工具、Web/PWA 归档、Android debug APK、OCI 镜像归档和 `SHA256SUMS`。APK 为 debug 签名，仅用于试用；本预发布不代表生产就绪。
