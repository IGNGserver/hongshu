# 鸿枢 v0.2.0-alpha.15

本版本在 v0.2.0-alpha.14 基础上，加固 PWA Web Push 通知与订阅恢复。仍为 alpha 预览版，不是稳定版。

## 本次更新

- **iOS/iPadOS 16.4+**：Safari 标签页现在明确提示先通过“分享 → 添加到主屏幕”安装 Web App，再从主屏幕图标打开并授权；不再只把通知开关置灰。
- **订阅恢复**：VAPID 密钥变化、浏览器轮换订阅或服务端因 404/410 清理订阅后，Web 端会在启动时和 `pushsubscriptionchange` 中重新订阅并绑定当前设备身份。
- **测试通知**：设置页新增“发送测试通知”，调用 `POST /api/push/test` 只向当前设备发送一条通用通知；不依赖真实短信，不写入短信，也不经过 Push 队列。未订阅、通知关闭、订阅失效分别返回明确错误。
- **PWA 安装与 manifest**：服务端显式以 `application/manifest+json` 提供 manifest；构建时校验 `display=standalone`、稳定 `id` 和 any/maskable 图标，降低 iOS 主屏幕安装失败风险。
- **通知安全**：Service Worker 对推送标题/正文做长度限制，通知点击只允许同源路径，未知 payload 回退为通用通知。
- **投递网络**：Push 客户端优先使用解析到的 IPv4 地址，并在失败时回退其余地址；修复 Docker 默认 bridge 无 IPv6 而 DNS 先返回 IPv6 时，APNs/FCM 投递直接失败的问题。
- **兼容性**：`/api/me` 新增 `push_subscribed`；旧客户端可忽略。没有数据库迁移，已有短信、已读状态、设备身份和订阅数据不变。
- 标准 Web Push + VAPID 路线不变：iOS 走 APNs，Android Chrome 走浏览器内置 FCM；未引入 Firebase SDK 或第三方推送 SDK。

## 升级与回滚

升级中枢前先备份数据库和 `.env`，将部署目录的 `HONGSHU_VERSION` 设为 `0.2.0-alpha.15`，然后运行：

```bash
docker compose pull hub
docker compose up -d hub
curl --fail http://127.0.0.1:18473/healthz
```

本版本不改数据库 schema；若中枢健康检查失败，把 `HONGSHU_VERSION` 改回 `0.2.0-alpha.14` 并重启 hub，不要删除数据卷。

Web Push 还需要 HTTPS、`VAPID_PUBLIC_KEY`/`VAPID_PRIVATE_KEY` 和真实的 `VAPID_SUBJECT`。旧部署缺少密钥时可使用镜像内的 `/vapid` 生成；已有订阅后不要随意轮换密钥。iOS 用户必须从主屏幕 Web App 打开后授权，Safari 标签页没有后台推送。Android Chrome 通知还取决于系统通知权限和 FCM/Google Play 服务，无 GMS 的国产 ROM 不保证。
