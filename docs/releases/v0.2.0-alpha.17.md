# 鸿枢 v0.2.0-alpha.17

本版本在 v0.2.0-alpha.16 基础上，修复中枢离线期间收到的短信在重连后出现“一份已上传、另一份仍要求确认接收号码”的双份记录问题，并新增可逆的自动忽略策略。仍为 alpha 预览版，不是稳定版。

## 本次更新

- **同一条短信不再留下两份**：权威广播/收件箱副本被中枢接受后，若仍有未配对、无接收号码、正文相同、时间差不超过 60 秒且候选唯一的通知副本，客户端把通知身份与判重归属转移到权威记录，并移除待上传副本。通知重放不会再次生成记录，后续收件箱副本也不会被残留的通知身份吞掉。
- **自动忽略无法确认号码的短信**：设置 → 短信采集 → 号码与队列新增开关，默认关闭，要求至少一个已确认 SIM 号码。开启后，无法解析接收号码且不属于通知身份碰撞或格式错误的记录不再提示、不上传、不计入首页和设置摘要，也不出现在会话列表；待上传页“需确认接收号码”分组也提供“自动忽略此类”入口。
- **可逆处理**：待上传页单独显示“已自动忽略”区，可恢复并关闭自动忽略，或放弃全部；保存有效 SIM、出现权威广播/收件箱副本时自动解除。手机短信应用中的原短信不受影响。
- **诊断**：新增不含正文的采集事件，区分“重复通知副本已并入已上传短信”和“无法确认接收号码已自动忽略/恢复/放弃”，便于判断问题走了哪条路径。
- **兼容性**：只修改 Android 队列与界面，没有服务端 API、数据库 schema、同步协议或 Web 变更；升级不触发迁移，已有短信、已读状态、设备 token、Push 订阅和部署数据不变。
- **已知边界**：吸收依赖正文、60 秒窗口与唯一候选；极端情况下两个不同发件人发送完全相同正文仍可能被合并。`sim_not_confirmed`、通知身份碰撞和格式错误不纳入自动忽略。真机双卡与澎湃 OS 通知字段仍需目标设备验收。

## 升级与回滚

升级中枢前先备份数据库和 `.env`，把部署目录的 `HONGSHU_VERSION` 设为 `0.2.0-alpha.17`，然后运行：

```bash
docker compose pull hub
docker compose up -d hub
curl --fail http://127.0.0.1:18473/healthz
```

本版本不改数据库 schema；若健康检查失败，把 `HONGSHU_VERSION` 改回 `0.2.0-alpha.16` 并重启 hub，不要删除数据卷。数据库、备份和既有设备授权不受影响。
