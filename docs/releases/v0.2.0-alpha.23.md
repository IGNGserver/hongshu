# 鸿枢 v0.2.0-alpha.23

本版本为 alpha 预览版。

## 本次更新

- 中枢支持 `HONGSHU_DATABASE_URL` 连接外部/共享 MySQL：`mysql://` URL、TLS/私有 CA、连接池、启动预检和 schema 版本检查；仍兼容旧 `MYSQL_DSN`。
- 新增 `hongshu migrate` 子命令与 `HONGSHU_MIGRATE=auto|check|off`；迁移锁按 schema 隔离，共享库可用迁移账号执行 DDL、运行时账号只保留 DML 权限。
- 新增 `compose.external.yml` 和外部库部署文档；备份脚本支持 `MYSQL_HOST/MYSQL_PORT/MYSQL_USER/MYSQL_DATABASE`，外部库不再依赖内置 backup 服务。
- 短信、通话和联系人改为批处理提交；100 条短信的上传 SQL 从约 700–800 条降到十几条，锁持有时间同步缩短。
- `/api/me` 合并单行状态读取；WebSocket 改为每进程共享状态轮询；AI 回填/分析/Push 在空闲时等待唤醒，不再固定每秒/每三秒打库。
- 新增迁移 014：未读查询与 Push 领取索引；`/healthz` 增加数据库连接池、等待和延迟统计。
- 可选 Redis：`HONGSHU_REDIS_URL` 支持跨实例变更广播、未读数共享缓存和 AI worker 选主；只保存非敏感派生状态，Redis 故障回退到进程内缓存和数据库轮询。

## 升级说明

升级前备份数据库和 `.env`。本版本新增迁移 014，只增加索引，不删除短信、设备、游标或已读水位；内置库直接 `docker compose up -d` 即可应用。

使用外部/共享 MySQL 时，先以 `utf8mb4` / `utf8mb4_bin` 创建独立 schema，用迁移账号执行一次 `hongshu migrate`，再设置 `HONGSHU_MIGRATE=check` 启动运行时账号。部署包中的 `docs/DATABASE.md` 包含 URL、TLS、授权、备份和故障排查；`compose.external.yml` 只启动 hub。

回退时把 `HONGSHU_VERSION` 改回 `0.2.0-alpha.22` 并重新创建 hub，保留数据库卷，不要运行 `docker compose down -v`。旧镜像会忽略新索引；外部库回退前先确认 schema 兼容并保留备份。Redis 始终是可选缓存，关闭或删除 Redis 不影响短信写入。

## 验证

- 发布工作流会重新运行仓库校验、Go race/vet/build、真实 MySQL 集成与逻辑备份恢复、Web/PWA 测试和构建、浏览器 smoke，以及 Android 单元测试/lint/正式签名 APK。
- CI 使用隔离 MySQL 和模拟浏览器，不能代替真实设备、公共网络、外部/共享 MySQL 或浏览器 Push 验收。

## 已知限制

- 本版本仍为 alpha 预览版，不是稳定版。
- 外部 MySQL 的跨公网/VPN 延迟、TLS 私有 CA、共享实例压力和 Redis 服务端故障恢复需在目标环境验收。
- 本轮未引入派生未读计数表；使用迁移 014 索引、版本化缓存和批处理，真实大历史若仍出现慢查询再按实测迁移。
