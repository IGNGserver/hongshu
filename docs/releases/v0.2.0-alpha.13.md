# 鸿枢 v0.2.0-alpha.13

本版本在 v0.2.0-alpha.12 基础上，减少弱网下首批短信等待并优化 PWA 离线应用壳、Android 最近内容展示与同步轮转。仍为 alpha 预览版，不是稳定版。

## 本次更新

- **Web/PWA/桌面浏览器**：登录后先显示应用与当前会话，不再等待统计、联系人或 AI 队列；超时、离线和认证失效分别提示。静态资源内容 hash/长期缓存，离线壳优先；版本更新由用户确认，API 与短信正文不写入缓存。
- **Android**：本地会话摘要加快列表读取，最近内容展示不跳过可靠历史游标；后台下载与小批上传交替进行，低速网络下限制上传字节预算。采集队列、ACK、身份隔离及通知防重仍保留。
- **中枢协议**：支持可选元数据修订和最近会话只读快照；迁移 012 仅增加失效时钟，不删除短信。旧客户端可继续使用原 API。
- **兼容与回退**：中枢旧数据通过迁移保留。Android 本地数据库升级到 v15 后，旧 APK 不能直接降级打开该库；请勿以清除应用数据作为回滚手段。数据库 schema 无法兼容时，应先评估备份恢复，不要执行 down migration。

## 升级与回滚

中枢升级：先备份数据库，将部署目录 `.env` 中的 `HONGSHU_VERSION` 设为 `0.2.0-alpha.13`，再运行：

```bash
docker compose pull hub
docker compose up -d hub
curl --fail http://127.0.0.1:18473/healthz
```

若中枢健康检查或迁移失败，将 `HONGSHU_VERSION` 改回 `0.2.0-alpha.12` 并重启 hub；迁移 012 可由旧中枢忽略。不要删除迁移表或数据卷。回退 Android 客户端前，注意旧 APK 不能直接读取 v15 数据库。

- 同条件本机合成 Chromium 对照显示在每次 API 人工延迟 600ms/1000ms 时首批内容单样本约 2.88s/4.43s 降为 1.40s/2.43s。该对照不是实际网络、真机测量或 p95 保证。
- 用户真实手机、北京入口和生产公网 waterfall 未纳入自动化结果；不能据此宣称这些环境已达到性能目标。
