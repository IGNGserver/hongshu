# 鸿枢 v0.2.0-alpha.3

本版本是跨设备短信同步与 AI 分组能力增强的 alpha 预览版，不是稳定版。升级前请备份数据库和部署 `.env`；本版本包含会话索引与 AI 设置迁移。

## 本次更新

- **会话按发件人聚合**：同一发件人发送到多张 SIM 卡的短信现在属于一个会话；详情页保留每条短信的接收号码、来源设备和时间，不再因接收号码拆分会话。
- **AI 协议扩展**：支持 OpenAI Responses、OpenAI Chat Completions、Anthropic Messages 和 Google Gemini Generate Content，可在 Web 设置中选择协议并保留现有配置。
- **Android 采集可靠性**：统一通知、短信广播和短信库记录的发件人匹配；增强双卡场景、重复短信、ACK 丢失和 SIM 变更后的 outbox 对账，避免重复上传或误清理。
- **Web 分组操作**：分组标签增加左右箭头、垂直滚轮转换、拖拽和键盘操作；修复标签栏指针捕获导致普通点击失效的问题。
- **数据库与兼容性**：新增发件人会话索引和 AI 协议字段迁移，保留全部历史短信；新增跨端回归测试、API/架构/部署文档和浏览器冒烟覆盖。

## 升级与回滚

升级前做好数据库和 `.env` 备份，将 `.env` 中的 `HONGSHU_VERSION` 改为 `0.2.0-alpha.3`，执行 `docker compose pull hub` 和 `docker compose up -d hub`，再检查 `/healthz`、`schema_migrations` 和客户端同步状态。中枢会依次应用 `007_sender_conversation_heads` 与 `008_ai_protocol`；迁移不会删除历史短信。

`007` 将会话摘要从“发件人 + 接收号码”改为“发件人”，`008` 为 `ai_settings` 增加协议字段。不要在这些迁移完成后直接把镜像降回 `0.2.0-alpha.2`，因为旧服务端写入旧会话摘要结构可能不兼容；需要回滚时保留服务在本版本，或停止服务并从升级前已验证的数据库备份恢复后再使用旧版本。不要执行未审计的 `down.sql` 处理生产数据。

## 验证边界

合并前的完整 Hongshu validation CI（隔离 MySQL、Go race/vet/build、Web 测试/构建、Playwright 浏览器冒烟、Android API 28/33/35）已通过。发布工作流还会重新执行服务端、Web、Android 签名构建、APK 校验、部署归档校验和 GHCR 镜像发布。

真实外部 AI 服务调用、真机短信/双卡和生产环境升级演练未在本版本发布前执行；AI 协议测试使用本地 HTTP fixture。
