# 鸿枢 v0.2.0-alpha.8

本版本在 v0.2.0-alpha.7 审计整改之上，补齐短信全链路剩余缺口：验证码通知的持久化与单渠道、provider 补读与重建检测、
上传不再阻断接收、Push 终态与退避。仍是 alpha 预览版，不是稳定版。升级前请备份数据库和部署 `.env`。

## 本次更新

- **验证码通知持久化与单渠道**：
  - Android SQLite 升级至 version 11，新增 `otp_intents`：通知意图与消息页同事务提交，进程在提交后退出仍会在下次同步补发未过期验证码；
  - 每条验证码只占一个渠道：能立即展示时不再同时计入普通“有新短信”汇总，不再一条短信响两次；
  - 展示期限取服务端解析有效期与“短信时间 + 10 分钟”的较小者：离线很久后同步到的旧验证码不再高亮，展示超时按剩余时间；
  - 会话已读、全部已读、epoch 重置与身份切换都会撤销待发意图并取消已展示通知。
- **采集补读与重建检测**：
  - 扫描时正文或号码为空的行进入 `incomplete_provider`，按最近尝试轮转重读；扫描水位仍前进，不阻塞后续完整短信；
  - 维护任务比较 provider 最高 `_id` 与扫描水位，回退（短信库被清空/恢复）即重置水位重新扫描；“最高 ID 不变但整库替换”仍需人工核对。
- **上报不再阻断接收**：上传异常延迟到下载循环结束后才报告给同步任务，本机发送队列故障不再拖住接收其他设备短信。
- **服务端与 Push**：
  - 格式非法的消息只拒绝该条（`invalid_message`），同批有效短信仍提交；上传策略查询失败返回 503，不再伪装成 403；
  - Push 投递前跳过已在全局/会话水位内的已读消息（healthz `suppressed_read`）；429 尊重 `Retry-After`；
    `attempts>=50` 的任务删除（healthz `dropped`）；404/410 清理该设备全部待发任务与订阅；
  - 迁移 `010_message_read_index` 为未读/会话查询增加索引，仅新增索引、可单独回滚。
- **边界与诊断**：
  - `X-Forwarded-Host` 仅在 `TRUSTED_PROXY_CIDRS` 内的可信代理参与 Origin 匹配；
  - Android OkHttp 增加 45 秒整体超时；诊断页显示通知兜底失败原因（脱敏）。

## 升级与回滚

升级前做好数据库和 `.env` 备份，将 `.env` 中的 `HONGSHU_VERSION` 改为 `0.2.0-alpha.8`，执行 `docker compose pull hub`
和 `docker compose up -d hub`，再检查 `/healthz`、`schema_migrations` 和客户端同步状态。中枢会自动应用 `010_message_read_index`
（只新增索引，不删除任何数据）。Android 客户端首次启动会就地升级到 SQLite v11，保留未上传队列、捕获账本与已读水位。

如需回滚，可将 `HONGSHU_VERSION` 改回 `0.2.0-alpha.7` 并重新启动容器；索引保留不影响旧版本运行。
