# 鸿枢 v0.2.0-alpha.9

本版本在 v0.2.0-alpha.8 基础之上，发布 Android 端短信采集统一链（P0–P4 阶段重构）：包括通知分类与兜底过滤、通知作为信号联动收件箱补读与暂缓上传机制、采集调度统一入口与游标收敛、待上传页状态精细化展示（核对中/仅通知），以及诊断页新增不含内容的采集事件日志。仍为 alpha 预览版，不是稳定版。升级前请做好数据库与部署环境备份。

## 本次更新

- **通知分类与兜底止血（P0）**：
  - 新增通知分类器（`classifySmsNotification`），精准识别并忽略前台服务与系统通知（如“短信正在运行”）；
  - 拦截并解析各类折叠与条数汇总通知（如 `[3条]`、`(3条)`、`N 条新信息`），汇总通知不再作为脏数据落库。
- **通知信号联动与暂缓上传机制（P1）**：
  - 通知只作为“有新短信到达”的信号，逐条消息仍以收件箱正文与元数据为准；
  - 开启通知兜底时联动申请权限并开启漏收检查；
  - 未配对的通知记录暂缓上传（号码类等待 30 秒，联系人/名称类等待 150 秒），放行前再补读一次收件箱，关联成功后立即放行并采用收件箱准确信息。
- **采集信号入口统一与游标收敛（P2）**：
  - 统一由 `requestCapture` 调度收件箱补读、通知关联与上传流程；
  - 推进历史水位时同步推进补漏水位（`recovery_provider_id`），避免多套机制重复扫描收件箱。
- **待上传状态精细化展示（P3）**：
  - 待上传列表区分 `NOTIFICATION_HELD`（正在与收件箱核对）与 `NOTIFICATION_ONLY`（只在短信通知中出现，允许指定号码或放弃），首页横幅同步提示状态。
- **采集事件本地诊断日志（P4）**：
  - Android SQLite 升级至 version 13，新增 `capture_events` 表，记录各来源（广播/通知/补读/漏收检查）的到达与配对结果代码；
  - 诊断页新增“采集事件”面板，支持导出诊断信息时一并附带（严格不包含任何短信正文与号码）。

## 升级与回滚

中枢升级：将部署目录 `.env` 中的 `HONGSHU_VERSION` 修改为 `0.2.0-alpha.9`，执行 `docker compose pull hub` 与 `docker compose up -d hub`。本版本服务端与数据库迁移无破坏性改动。

Android 客户端升级：安装新版本 APK 即可，本地数据库会自动从 v11/v12 就地升级至 v13（新增 `capture_events` 表），保留未上传队列、捕获账本及已读水位。

如需回滚，可将 `HONGSHU_VERSION` 改回 `0.2.0-alpha.8` 并重新拉起容器；Android 客户端降级需注意 SQLite 向下兼容性。
