# 鸿枢 v0.1.0-alpha.3

短信采集、上传确认和数据库回档的预览修复。必须在 GitHub 上显示为 **Pre-release**。不是正式版，不能当作生产安装源。

已有 `v0.1.0-alpha.2` 部署升级时会自动应用两条兼容迁移：推送任务增加 60 秒租约，同步时钟增加 `epoch`（默认 1）。不要在升级时手工加 epoch。只有把数据库恢复到更早备份、并且短信 ID 会重用时，才在启动中枢前执行部署文档中的 `UPDATE sync_clock SET epoch=epoch+1`。

## 修复

- Android 提高短信广播优先级，开机后重新登记补扫。已授予 READ_SMS 时，开机、打开应用和每次同步按收件箱水位补上漏掉的广播。自动补扫从本机配对时刻开始，更早的收件箱仍由用户显式导入。
- 同一设备、同一发件人、同一正文、时间差在 2 分钟内的收件箱导入不再变成第二条。卡槽不再当作号码身份；只有订阅 ID 精确命中，或用户明确确认本机只有一张 SIM，才自动填写接收号码。
- 会话按发件人加接收号码分组。同一短号发给两张 SIM 是两个会话。
- 同一上传批次里未确认的接收号码只标记该条 `sim_not_confirmed`，不再回滚同批已确认短信。客户端只删除已确认条目。
- 新设备第一次同步时，配对之后由其他设备上传的非历史短信仍发一条汇总通知。更早的历史不通知。
- Web Push 发送前领取 60 秒租约。过期订阅 404/410 只删除该 endpoint 自己的任务和订阅。
- 数据库回档后，客户端发现 `epoch` 变化会清空已同步缓存并从 0 重拉，未上传队列保留。游标已经超过恢复后的 sequence 时返回 `epoch_changed`，不再把空页当成同步完成。
- SQL 迁移拆分不再把字符串或注释里的分号当成语句结束。

## 仍未验证

本机没有双卡、Doze、强制停止、验证码脱敏、公网 HTTPS 或浏览器后台 Push 环境。这些没有端到端通过。用户强制停止后系统不再投递短信广播，必须重新打开应用。Android 没有远程唤醒。

## 回滚

应用镜像可回到 `v0.1.0-alpha.2`，但不要执行 `002`/`003` 的 down.sql，除非已确认没有客户端依赖新列。schema 不兼容时恢复升级前的数据库备份，不要在生产库上丢列。已发布的 tag 和本 Release 不覆盖、不重发。
