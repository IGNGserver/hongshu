# 鸿枢 v0.1.0-alpha.4

单密码 Web 登录与可选 HTTP 部署预览。此版本必须作为 GitHub **Pre-release** 发布；仍是 alpha，不建议用于存放重要短信的日常生产服务。

## 新增与调整

- Web 不再要求用户名、首次初始化密钥或浏览器配对码；使用部署配置的 `HONGSHU_PASSWORD` 登录。允许弱密码，但不允许空密码。每次新浏览器登录会建立一个管理员 Web 设备会话。
- Android 继续使用管理员生成的一次性配对码和逐设备 token；数据库结构及现有短信、设备和授权记录无需迁移。
- `PUBLIC_URL` 支持 HTTP 和 HTTPS。Android 支持 HTTP/HTTPS 与对应的 WS/WSS 实时连接；Compose 默认仍只绑定宿主机回环地址，直接外网访问需显式设置 `BIND_ADDRESS=0.0.0.0` 并配置防火墙。
- HTTP 不加密密码、会话凭据、短信正文或 API 数据。公网链路上的第三方可能窃听或篡改；优先使用 HTTPS 或 VPN。公网 HTTP 下浏览器 Service Worker、可安装离线应用和 Web Push 不可用。
- 改变 `HONGSHU_PASSWORD` 不会自动撤销既有 Web 会话；请在设备页撤销旧浏览器会话。密码保存在受保护的部署环境/`.env`，不得写入 issue、日志或仓库。

## 升级与回滚

从 `v0.1.0-alpha.3` 升级不需要数据库迁移。在现有 `.env` 中添加 `HONGSHU_PASSWORD` 后重建 hub；旧 `BOOTSTRAP_SECRET` 不再用于登录。Android `versionCode` 从 2 升至 3。

回滚到 `v0.1.0-alpha.3` 时恢复旧版 Compose/服务配置，并确保 `.env` 中仍有符合旧版要求的 `BOOTSTRAP_SECRET`。数据库 schema 未变化，旧版可以继续识别已有设备 token/cookie 和短信数据；旧版浏览器仍可用配对码添加 Web 设备。不要删除 MySQL 数据卷。

## 验证边界

发布工作流在隔离 MySQL 上运行 Go race/integration 与真实浏览器 smoke test，并构建 Web、Android 和 OCI 归档。明文 HTTP 的公网连通性与链路安全必须由部署者在目标网络单独验收；不能把构建通过视为安全传输。

## 资产与性质

发布工作流会生成 Linux amd64 中枢/工具、Web/PWA 归档、Android debug APK、OCI 镜像归档及 `SHA256SUMS`。这是 alpha 预览，不是正式稳定版；Release 和 tag 不覆盖、不重发。
