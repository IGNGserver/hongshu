# PWA installation and adaptive Web layout

The product Web origin is the installable application. It does not require a separate mobile or PWA URL. Its stable manifest is `/manifest.webmanifest`, application id and scope are `/`, and the public worker is `/sw.js`. The website under `website/` is a separate download site.

Production builds use Workbox injectManifest and locally bundle its runtime. Each release precaches an atomic, versioned public shell and rejects stale HTML or invalid script/style types; content-addressed public assets can be reused across releases. Activation waits for the user to choose an update. Old shell caches stay available to already-open documents. Neither authenticated API responses nor SMS content enter Cache Storage. Push and subscription rotation continue to use the existing worker and session checks.

The HTML declares opaque Apple touch icons (180, 167 and 152 pixels) and ordinary/maskable PNG icons. Builds pin icon URLs to their contents while preserving root fallback names. The manifest URL stays stable and its icon references are versioned. HTML, the manifest and SW are served with no-store/no-cache; hashed public assets are immutable. A proxy/CDN must respect these origin headers or bypass cache for the business origin's HTML, manifest and worker. Do not change cache policy for unrelated hosts.

Installation help remains available on the login and settings pages. Chromium's install prompt is used only when the browser supplies one; iPhone/iPad use Share > Add to Home Screen. Missing beforeinstallprompt does not prove that installation is unsupported. The installed icon and standalone launch require real-device acceptance, including existing installations and new installations.

Layout follows the available window, including tablet split-screen. Below 600 CSS pixels, inbox/detail share one pane; at 600 pixels and above, the inbox uses a bounded proportional width beside detail. Wide tablets retain touch targets. Safe-area insets are applied once around the application. visualViewport tracks software-keyboard height and offset without changing pinch-zoom behavior. Login, settings, detail, menus and installation/update dialogs remain scrollable in short windows.

Validation includes Node tests, built-artifact checks and an isolated browser PWA regression (`scripts/pwa-browser-smoke.cjs`). The browser test uses synthetic API responses, never a real account or SMS. Chromium uses an offline browser context. WebKit uses an unavailable-origin fixture with an uncontrolled-page failure comparison because its automation offline mode cannot reliably navigate through a Service Worker. iOS Home Screen icons and Android Edge installation must also be checked on the target device; desktop emulation cannot attest to the OS installer.
