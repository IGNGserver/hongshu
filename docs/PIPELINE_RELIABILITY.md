# 短信链路可靠性实施

基线：`8c6d5d7`（`0.2.0-alpha.7`，含 #65 审计整改），任务 `agent/pipeline-reliability`，版本号不变。
本文件只记录本次在既有整改之上补做的部分；已被 #65 覆盖的机制（已读下行协议、通知身份去重、
上传指纹账本、OTP tag 隔离、Push 订阅复活竞态）不在此重复。

## 已实现

| 编号 | 契约 | 实现 |
|---|---|---|
| 1 | 验证码通知持久化 | SQLite v11 `otp_intents` 与消息页同事务提交；进程中断后仍可补发未过期验证码 |
| 2 | 验证码单渠道 | 能立即展示时进入 OTP 意图并从普通汇总计数扣除，否则只计普通通知，不再双响 |
| 3 | 有效期 | 服务端解析的有效期与“短信时间 + 10 分钟”取较小值；过期不排队、不展示，展示超时按剩余时间 |
| 4 | 已读撤销 | 会话/全部已读、epoch 重置、身份切换都会撤销意图并取消已展示通知 |
| 5 | provider 补读 | 扫描时字段为空的行进入 `incomplete_provider`，按最近尝试轮转重读；水位仍前进，不阻塞后续短信 |
| 6 | provider 重建检测 | 维护任务比较当前最高 `_id` 与扫描水位，回退即重置水位重新扫描 |
| 7 | 上传不再阻断接收 | 上传异常延迟到下载完成后才向 worker 报告，接收其他设备短信不再被本机发送队列拖住 |
| 8 | 逐条非法消息 | 服务端对格式非法消息返回该条 `invalid_message`，同批有效短信仍提交 |
| 9 | 数据库故障分类 | 上传策略查询失败返回 503，不再伪装成 403 `upload_disabled` |
| 10 | Push 已读抑制 | 投递前检查全局/会话水位，已读消息直接删除任务并计数 `suppressed_read` |
| 11 | Push 终态与退避 | 429 尊重 `Retry-After`；`attempts>=50` 的任务删除并计数 `dropped`；404/410 清理该设备全部任务与订阅 |
| 12 | 查询与边界 | 迁移 010 增加未读索引；`X-Forwarded-Host` 仅在可信代理内参与 Origin 匹配；OkHttp 增加 45 秒 call timeout |
| 13 | 诊断 | healthz 新增 `suppressed_read`/`dropped`；Android 诊断页显示通知兜底失败原因（脱敏） |

## 兼容与迁移

- SQLite v11 仅新增 `otp_intents`、`incomplete_provider` 两表；升级不清除任何已有队列、账本或水位。
- MySQL 迁移 010 只新增索引，down 只删除该索引。
- `invalid_message` 逐条 ACK 与既有客户端契约一致：已发布客户端在 `uploadAcks` 中已接受该错误类型并按条阻塞；
  旧中枢仍可能整批 400，客户端保留二分隔离路径。
- 旧客户端（无 `capture_ids`/意图概念）行为不变；服务端不要求新字段。

## 未实施项与理由

- O06 采集事务瘦身、O07 更细的未读索引评估：需要真实 MySQL 的锁等待/执行计划基线后再动。
- O10 Push 按设备合并、O14 备份保留策略与告警通道：属产品与运维决策（通知合并语义、保留期限），
  项目规范要求不提前选择。
- 阶段 8 的真机、API 36 胶囊、公网 Push、真实 MySQL 恢复演练：本机无 adb 设备、无 MySQL/Docker，
  由 PR CI 与后续目标环境验收承担，不以本机结果代替。

## 验证环境

本地快速验证仅使用 `~/.build/短信同步系统/pipeline-reliability/` 源码副本和共享缓存。
`adb devices -l` 当前没有连接设备；真机和公网 Push 验收需在获得相应环境后记录真实结果。
