HONGSHU · 私有短信中枢

多台手机的短信，
安静归入自己的中枢。

手头有多部主力机、双卡备用机或工作号？鸿枢（Hongshu）把散落在各台手机上的收发短信与只读通话记录，沿加密链路汇聚到你自托管的 Go + MySQL 中枢——无需 Google 服务，不经第三方云端，在桌面 Web/PWA 与授权 Android 设备上随时查阅、筛选与复制验证码。

STAGE 01 · 手机端可靠采集

多卡手机各自安静采集，断网与切卡不丢信。

开启实时同步仅需授予 RECEIVE_SMS 权限，不依赖 Google Play 服务（FCM），无需设为默认短信应用，也不申请无障碍权限。广播捕获后先写入本机 SQLite 恢复表与 outbox 持久队列，经服务端明确确认后才消费。

  • 按系统 SIM 订阅 ID 精确绑定接收号码，换卡槽绝不把新卡短信错记到旧号码
  • 针对 HyperOS 等系统提供可选通知信号协同补读，自动匹配并吸收重复副本
  • “补齐历史短信”（READ_SMS）与“同步通话记录”（READ_CALL_LOG）均独立开关授权
STAGE 02 · 汇入私有 MySQL 中枢

直连你自己的基础设施，顺序可证、备份一致。

多台手机捕获的消息直接提交至你部署在家庭服务器、NAS 本地盘或私有云上的 Go + MySQL 8.0+ 中枢。服务端锁定单例 sync_clock 分配严格提交顺序，并以 SHA-256 指纹幂等去重，既消除同源重试又不误合并不同手机收到的相同通知。

  • 单一中枢密码（Argon2id 内存校验）配合每设备独立 256-bit Bearer 凭据，支持随时单设备撤权
  • 入库事务内同步执行版本化规则验证码提取，无需外发即可识别 4–8 位验证码与明示有效期
  • sync_clock.epoch 守护一致性逻辑备份与灾难恢复，回档后客户端自动对齐新代次
STAGE 03 · 桌面与多端即时查阅

镜头转向桌面：同一条消息，在所有授权端从容就位。

WebSocket 与 Service Worker 仅传递无正文的轻量变更提示，桌面浏览器、平板独立 PWA 窗口与其他仅查看手机随即增量拉取最新会话。无论备用机留在书房充电还是静音放在包里，验证码与重要通知都能在手边设备一眼读取。

  • Material 3 Expressive 视觉体系：Android 原生 Compose 客户端与零框架 Web/PWA 共享一致体验
  • Android 16+ 支持跨设备新验证码状态栏实时胶囊（仅其他设备同步消息触发，不干扰本机弹窗）
  • 查看端可选本机通讯录姓名与头像装饰，数据仅留当前设备本地，绝不写入中枢

CRAFT & RELIABILITY · 为长期自部署打磨

克制而周密的通信工程细节。

通信工具的价值在于日常无感与关键时刻可靠。鸿枢在采集账本、分页游标、离线壳更新与跨端交互上都采用可审计的确定性设计。

01

零 GMS 依赖与低功耗驻留

Android 客户端完全不依赖 Google Play 服务。支持 WorkManager 网络约束指数退避同步，以及可选的 Android 14+ remoteMessaging 实时前台服务，状态栏如实区分连接握手与实际同步健康。

Kotlin · Jetpack Compose · Material 3 Expressive
02

原生零框架 Web/PWA 客户端

内置 Web 端可添加到桌面或 iOS/iPadOS 16.4+ 主屏幕运行，支持 VAPID 标准 Web Push、应用角标未读数同步与通知一键聚焦对话；短信正文与验证码仅驻留内存，绝不写入浏览器 localStorage 或 Cache Storage。

Service Worker 原子壳租约 · head/epoch 游标分页
03

本机通讯录零上传显示层

Android 通过 PhoneLookup 完整号码比对，Web/PWA 通过浏览器 Contact Picker API 将所选联系人保存在独立本地库中。姓名与头像只装饰当前查看设备界面，绝不上传至中枢或跨设备同步。

BOUNDARIES · 透明功能与隐私边界

能做什么，不能做什么。

自托管软件建立在诚实说明之上。在部署鸿枢前，请清楚了解以下产品能力边界与安全前提。

明确边界 · 只读归集

收发记录与通话记录只读查看

同步手机本机已收到与已发送的短信记录，以及可选开启的系统通话记录，供所有已授权 Android 与 Web/PWA 设备检索查看。鸿枢不处理彩信（MMS）或富媒体消息（RCS），不通过运营商代发短信，也不代替你拨打电话或触发跨端来电振铃。

基础设施 · 自主掌控

自己的服务器与 MySQL 8.0+

由单二进制 Go 服务与 MySQL 8.0+（utf8mb4_bin）构成，官方容器镜像发布于 ghcr.io/igngserver/hongshu（支持 linux/amd64 与 linux/arm64）。全部消息、设备凭据哈希与逻辑备份均保存在你自己的本地磁盘上。

安全前提 · 非端到端加密

传输与静态存储保护责任

首版不提供端到端加密（E2EE）：中枢数据库与逻辑备份持有完整短信明文，以便服务端执行全文搜索与规则提取。公网访问请务必配置 HTTPS 反向代理或 VPN；Android 客户端默认拒绝明文 HTTP，仅允许对受控局域网源逐项显式授权。本官网与所有示例均不展示任何真实短信、真实手机号或个人数据。

默认关闭 · 可选外部模型

可选 AI 分组的数据流向

鸿枢默认不启用 AI，日常验证码提取完全由本地版本化规则完成。仅当管理员在中枢设置里主动配置并开启可选 AI 分析时，短信正文会发送给你选择的服务商（如 OpenAI、Anthropic、Gemini 或白名单自建模型）；启用前请务必审查所选服务商的隐私政策、服务地域与数据留存设置。

SELF-HOSTING · 先读对应版本文档，再部署

在自己的 Linux 主机上三步启动。

鸿枢当前仍处于预发布阶段（v0.2.0-alpha.26）。请仅从 GitHub Releases 获取已发布的安装包与容器标签，并严格对照同一 Release 标签下的部署与恢复文档操作，避免混用开发分支说明。
